# utils

This directory has the scripts that generate data for the Foundation sources.

## Locale data

`_FoundationInternationalizationData` has generated tables of locale data:

| Table | Holds |
|---|---|
| `DateFormatData.swift` | Date names, such as months, weekdays, eras, and day periods, and GMT formats |
| `LocaleNumberData.swift` | Each locale's numbering systems, the digits of each numbering system, and number symbols |
| `LocaleIDData.swift` | The locale IDs, redirects, and fallback locale that the date and number tables share |
| `ListFormatData.swift` | List patterns, such as "{0}, {1}" and "{0} and {1}" |

The tables come from CLDR XML in two stages. Each stage has one script that handles all the tables.

```
CLDR XML
   │  update-locale-data
   ▼
DateFormatData.json, LocaleNumberData.json, ListFormatData.json
   │  build-locale-data
   ▼
DateFormatData.swift, LocaleNumberData.swift, LocaleIDData.swift, ListFormatData.swift
```

Both the JSON files and the Swift files are in the repository, so you only run these scripts to change the data.

### Update the JSON from CLDR

Run `update-locale-data` when you move to new CLDR data. Set `CLDR_PATH` to the CLDR root, the directory that contains `common/main/` and `common/supplemental/`:

```sh
CLDR_PATH=/path/to/cldr utils/update-locale-data
```

The script writes `DateFormatData.json`, `LocaleNumberData.json`, and `ListFormatData.json` in `Sources/_FoundationInternationalizationData`. It replaces the files only if all of them succeed.

Use the same CLDR data that the committed JSON came from, unless you mean to update the data. A different copy of CLDR, even of the same version, can change existing names.

### Build the Swift tables

Run `build-locale-data` after you update the JSON:

```sh
utils/build-locale-data
```

The script writes all of the data tables in `Sources/_FoundationInternationalizationData`.

| Option | Effect |
|---|---|
| `--locales=en,ja,ar` | Includes only these locales plus "root". The default is all locales. |
| `--fallback=en_001` | Fallback locale identifier if we cannot resolve a locale identifier to any of the included locales. The default is "root". The data for this locale is also included. |
| `--output-dir=path` | Writes the Swift files to this directory instead of the source tree. |

All the tables share the same locales and fallback.

Each generated file has a header that shows how it was built:

```
// Generated by utils/build-locale-data. Do not edit by hand.
// CLDR version: 48
// Locales: all
// Fallback: root
```

## Adding data

Each kind of data has a schema, an update tool (CLDR XML to JSON), a build tool (JSON to Swift), and a lookup file that reads the generated table. To change the data, edit these files, run `update-locale-data` and `build-locale-data`, and add a test with fixed expected values.

| Data | Files |
|---|---|
| Date names | `date-format-data-schema.swift`, `update-date-format-data-impl.swift`, `build-date-format-data-impl.swift`, `DateFormatLookup.swift` |
| Numbering systems and number symbols | `locale-number-data-schema.swift`, `update-locale-number-data-impl.swift`, `build-locale-number-data-impl.swift`, `LocaleNumberLookup.swift` |
| List patterns | `list-format-data-schema.swift`, `update-list-format-data-impl.swift`, `build-list-format-data-impl.swift`, `ListFormatLookup.swift` |
| Locale IDs and redirects | `build-locale-id-data-impl.swift`, `LocaleIDLookup.swift` |

To add a new kind of data, add the same four files. Then add the new table to `update-locale-data`, `build-locale-data`, `CMakeLists.txt`, and `Package.swift`. If the table holds data for each locale, add it to `build-locale-id-data-impl.swift` too.

## IANA character set names

`update-iana-charset-names` generates `IANACharsetNames.swift`, the list of IANA character sets. See the comments at the top of the script.
